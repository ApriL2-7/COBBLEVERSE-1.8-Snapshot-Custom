# 클라이언트 애니메이션·지닌 물건·리소스 설정 수정

## 확인한 원인

1. Fomantis의 ATMxMSD poser는 `battle_idle`, `eyes_angry` 등 기존 동작을 참조하지만, 높은 우선순위의 번역 팩이 같은 애니메이션 파일을 더 작은 최신 동작 목록으로 덮어씁니다. 동작을 찾지 못해 poser 역직렬화가 실패합니다.
2. Cobblemon 1.8.3의 지닌 물건 동기화가 클라이언트 Pokemon 이벤트를 발생시키고, 일반 콜백 리스너가 `HeldItemEvent.getContext()`를 부릅니다. 이 함수는 `server()!!`로 서버 레지스트리를 요구하므로 멀티플레이 클라이언트에서 null 예외가 납니다.
3. 리소스팩 설정의 외부 JSON은 유효하지만 title/description 안의 텍스트 JSON 일부가 유효하지 않아 Resource Pack Overrides가 설정 읽기를 중단합니다.

## 변경

`updater/Cobbleverse-ClientRepairs.ps1`을 통합 프로필 업데이트 경로에 연결합니다. 기존 BAT 파일은 바꾸지 않습니다. 이전 PC 모드 업데이트가 성공한 다음 새 수정을 처리합니다.

- 설치된 모드와 활성 ZIP 리소스팩의 포켓몬 애니메이션을 검사해 보정 리소스팩을 만듭니다. 높은 우선순위 파일에 남아 있는 동작과 메타데이터를 그대로 보존하고, 덮어쓰기로 사라진 동작 이름을 원본에서 복원합니다. 다른 모델이나 한국어 번역을 교체하지 않습니다.
- 추가 로그에서 확인한 Vileplume의 `quirk` 누락도 처리합니다. Cobblemon은 디렉터리와 무관하게 파일명으로 애니메이션 그룹을 등록하므로, 파일명이 같은 여러 경로에 모두 동작 이름을 보존합니다. 원본 어디에도 없는 동작은 새로 만들지 않습니다. 애니메이션이 있는 폴더형 리소스팩은 안전하게 중단하고 ZIP 변환을 안내합니다.
- 리소스팩 제목·설명 컴포넌트를 JSON으로 다시 직렬화하고, 보정 팩을 활성 목록의 마지막에 둡니다. 단축키·그래픽·감도·월드는 유지합니다.
- MIT 라이선스의 2,641바이트짜리 `cobbleverse-client-callback-guard-1.0.0.jar`를 설치합니다. 이 모드는 클라이언트 Pokemon 또는 서버 컨텍스트가 없는 경우 지닌 물건/치장 아이템의 **서버 스크립트 콜백 리스너만** 건너뜁니다. 아이템 동기화 및 다른 이벤트 리스너는 유지합니다.
- 설치 대상은 Cobblemon 1.8.3으로 제한하고 실제 CallbackHandler 클래스 SHA-256과 네 개 Mixin 대상 서명을 대조합니다. 게임 실행 중·잘못된 다운로드 해시·지원하지 않는 구현에서는 변경을 거부합니다.
- 기존 설정과 보정 팩은 프로필의 `.cobbleverse-client-repair-...` 폴더에 백업합니다. 재실행 시 동일한 내용이면 다시 설치하지 않습니다.

서버 전용 수정이 아니므로 서버에 새 모드를 넣거나 서버를 재시작하지 않습니다. 생성하는 보정 리소스팩에는 사용자가 이미 설치한 동작을 사용하며, 그 리소스팩이나 제삼자 모드 JAR를 저장소/배포 자산에 올리지 않습니다.

## 검증

- 실제로 컴파일한 가드 함수를 JVM `-Xverify:all`로 실행해 client/server 상태 8개 경우 확인.
- 실제 Cobblemon JAR의 네 개 콜백 대상 서명 확인.
- 실제 충돌 팩에서 추출한 동작/설정을 사용한 격리된 PowerShell 설치·백업·재실행 검사.
- 지닌 물건 수정 JAR 해시, 리소스 ZIP CRC, 필수 동작과 새 기본 동작이 함께 존재하는지 검사.
- 설정 컴포넌트 126개 엄격 JSON 검사.
- 잘못된 해시 및 실행 중인 게임에서 설치 파일이 바뀌지 않는지 검사.
- 개인 설정·월드 진행 표시 파일 보존 및 로컬 전체 모드팩 CRC/모드 해시 검사.

요청에 따라 Minecraft를 직접 실행하지 않았습니다. 실제 Mixin 적용과 게임에서 지닌 물건 교환·Fomantis 렌더링은 아직 확인하지 않았습니다. 기존 REI 비동기 검색 취소 경고와 별도의 서버 저장/전투 AI 문제는 이번 세 수정의 범위에 포함하지 않습니다.

## 공개 반영 순서

1. 소스와 검사 결과 검토. 2026-10-28 사용자 지시에 따라 이 모드팩 수정의 main 병합 전 별도 승인 조건은 철회되었습니다. 이후 검증을 마친 수정은 추가 승인 질문 없이 PR을 통해 main에 반영합니다.
2. 초안 Release `v2026.10.27-clientfix1` 공개: 자체 MIT 모드 JAR, 전체 자체 소스 ZIP 및 해시 기록만 포함.
3. 업데이터 PR을 main에 병합. 파일 다운로드 경로가 공개되기 전에는 병합하지 않습니다.
4. 기존 BAT를 실행하면 PC 수정 이후 추가 클라이언트 수정이 적용됩니다.

라이브 게임 검증 전의 수정이므로 Release는 prerelease로 표시합니다.

## 라플레시아 수정 후속 검증

친구 로그의 활성 ZIP 팩 순서를 별도 프로필로 재현했습니다. 384개 파일에서 덮어쓰기로 사라진 동작 이름 1,821개(파일별 중복 포함)를 복원했습니다. 모든 출력 JSON을 별도의 Python 검사기로 원본과 대조해, 기존 동작 값과 메타데이터 보존 및 라플레시아 `quirk` 복원을 확인했습니다.

일반 동작과 quirk의 문자열 참조 12,241개를 정적으로 검사했으며, 원본에서 복구 가능한 누락은 572개에서 0개가 됐습니다. 원본에도 없는 참조 50개와 엄격 JSON으로 읽히지 않는 기존 poser 3개는 별도로 남아 있습니다. 이 검사는 모든 모델이 실제 선택되는지 판정하지 않으며, 내장 변형 팩·동적 표현식·게임 렌더링 검증을 대신하지 않습니다. 따라서 모든 렌더링 오류가 해결됐다고 보장하지 않습니다.

Windows PowerShell 5.1에서 최초 설치, 재실행 시 파일 해시와 백업 수 유지, 잘못된 JAR 해시 및 실행 중인 게임에서 변경 거부를 검사했습니다. SHA-256 계산은 PowerShell 모듈 자동 로딩에 의존하지 않습니다. 새 모드 JAR나 Release 자산은 필요 없으며, 기존 BAT가 받는 스크립트만 갱신하면 됩니다. main 병합 전 별도 승인 조건은 위 사용자 지시에 따라 철회되었습니다.
